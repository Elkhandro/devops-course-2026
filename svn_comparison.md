# SVN vs Git

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

В Git ветка — это просто указатель на коммит (ссылка). Создание ветки не копирует файлы, а лишь создаёт новый указатель. Это операция за O(1), мгновенная и не требующая места.
В SVN ветка — это копирование директории в репозитории. Даже если SVN использует «лёгкие» копии (cheap copies), это всё равно операция на стороне сервера, требующая сетевого взаимодействия. Ветвление в SVN медленное и «дорогое» по сравнению с Git.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет, нельзя. SVN — централизованная система. Коммит в SVN — это операция, которая отправляет изменения на центральный сервер. Без подключения к серверу коммит невозможен. Можно лишь работать с локальной рабочей копией, но зафиксировать изменения в истории — только через сервер.
В Git коммит делается локально, без интернета, потому что у вас есть полная копия репозитория.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

- Legacy-проекты: старые системы в госсекторе, банках, где SVN уже используется и переход на Git дорог.
- Очень большие бинарные файлы: SVN лучше работает с большими бинарными файлами.
- Простота для нетехнических команд: SVN проще в освоении.
- Централизованный контроль: если нужен жёсткий контроль доступа и единая точка истины.
- Частичный checkout: SVN позволяет выкачать только часть репозитория.
